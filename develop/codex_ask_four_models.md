## 1. 빈칸이 가능한 이유 — 리졸버가 이미 알고 있습니다

`src/symbolic_shape.py:371` 의 `_pick()`:

```python
ms = [s for s, v in cands if n == v and ...]
if len(ms) > 1:
    ties[(module_path or "", n, tuple(sorted(ms)))] += 1
return ms[0]          # 전역 우선순위 = 관례이지 근거가 아니다
```

같은 값을 가진 후보가 둘 이상이면 **임의로 하나를 고르고 그 사실을 기록**합니다. 함대 전체:

```
임의 선택 축 465,213 (전체의 3.7%)  ->  질문 120개 / 모델 30개
   122,496축  6질문  Qwen3.5-397B-A17B
    27,282축  9질문  DeepSeek-V4-Pro
    25,364축 12질문  DeepSeek-V4-Flash(-0731)
    17,892축  1질문  Llama-3.1-405B
```

같은 `(module_key, value, candidates)` 질문 하나가 수천 축을 덮으므로, **전부 빈칸으로 바꿔도
물어볼 것은 120개뿐**입니다.

`develop/promote.py:39`:

`review_findings.json` / `.md` 는 ③층이 쓰는 파일이고 트레이스가 재생성하지 않아 **promote

## 4. 제안 — 빈칸을 일급으로

`_pick()` 이 `len(ms) > 1` 일 때 `ms[0]` 대신 **자리표시자**를 돌려줍니다. 자리표시자는
질문 하나에 대응하고, 답 하나가 그 질문의 모든 축을 채웁니다.

```
prefill.csv   [[B, ?1, T, ?2]]        <- 지금은 [[B, n_h, T, d_head]]
open_axes.json
  {"id": "?1", "module": "model.layers.*.self_attn", "value": 64,
   "candidates": ["d_head", "n_h"], "axes": 5616, "sites": [ ...예시... ]}
```

근거 우선순위는 값을 안 보는 것부터입니다: 모듈 선언 폭 -> 모듈-필드 멤버십 -> 소스 대조
-> 다중 길이 프로브 -> **LLM 판정** -> ③ 자유 평가.

LLM 답에는 ① 확정 이름 ② **소스의 어느 줄** ③ **반증 조건**이 반드시 있어야 하고, 셋 중
하나라도 없으면 채택하지 않고 빈칸으로 남깁니다. 인용 줄은 실제 파일에서 다시 읽어 문자열
일치를 기계적으로 확인하고, 채택분만 `rules/label_overrides.yaml` 에 `source:` 를 달아
넣습니다.
