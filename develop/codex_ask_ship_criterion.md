# 출고 기준을 바꾸려 합니다 — "질문 0" 대신 중요도 가중 + 알려진 오라벨 0

## 1. 먼저: 배치 방향은 반영했고 결과가 좋습니다

`resolve_capture_sizes(cfg, base_seq)` 가 `(B, T)` 를 함께 고릅니다. Llama-4 는 `(3, 16)`.

```
prefill  [[B*T, d_model], [d_model, n_h*d_head]]   -> [[B*T, n_h*d_head]]
         [[B*n_h, T, d_head], [B*n_h, d_head, T]]  -> [[B*n_h, T, T]]
decode   [[B*n_h, 1, d_head], [B*n_h, d_head, T+1]] -> [[B*n_h, 1, T+1]]
```

resolver 변경: `build_resolver(cfg, seq_len, batch=)`, B>1 이면 크기 1 은 리터럴 `1`,
배수가 배치와 같으면 `B*<심볼>`(관측된 배치와 일치한다는 증거가 있으므로 추측이 아님),
세 인자 곱 `B*E*T`(MoE routed 입력). `provenance.capture_batch` 도 남깁니다.

**독립 검증(B=4)**: 어긋난 라벨 0 / 짝 못 지은 op 0 / 배치 차수 위반 0.
B=1↔B=2 에서 나던 연속성 밀림 1,092 op 도 B=3↔B=4 에서는 0 입니다.

미완성이던 `b_dep` 보정 장치는 버렸습니다.

## 2. 그런데 출고 기준이 이 개선을 못 봅니다

지금 기준은 `review_request.md` 의 **"판단 필요 0건"** 인데, 그건 "자동 규칙이 전부
결정했다" 는 뜻이지 정확도가 아닙니다. 실제로 **B=1 판도 "질문 0" 이었습니다** -- 접힌
배치가 3,962축 틀린 채로.

## 3. 제안하는 기준과 실측

```
알려진 오라벨 0     label_false / 등가류 두 이름 / 배치 차수 위반 /
                    검증 배치 불일치 / dead override / 낡은 근거
파라미터 축 설명    99%+   (가중치는 config 가 선언하므로 설명 가능해야 한다)
주요 op 축 설명     95%+   (사람이 읽는 표)
미확정 축          허용. 단 사이드카에 등급과 이유가 반드시 있을 것
```

5개 모델 실측(파라미터 축 = `weight_shape` 의 축, 주요 op 축 = 발행 csv 의 축):

## 4. 이 측정에서 드러난 문제

**커버리지 %만으로는 B=1 과 B=3 을 구분하지 못합니다.** 둘 다 94.2% 입니다 -- `3*n_h` 나
`n_h`(접힌 배치 누락)도 "정수가 아니므로 이름 있음" 으로 세기 때문입니다.

즉 **커버리지는 필요조건일 뿐이고, 실제 무게는 "알려진 오라벨 0" 쪽에 있습니다.** 그렇다면
커버리지 임계값(99%/95%)은 무엇을 위한 것인지 다시 생각해야 할 것 같습니다.

커버리지는 보고만 하는 편이 낫습니까?

산출물이 없는 것보다 낫고, KDA 참조 구현의 내부 축은 애초에 아키텍처 설명에 필요 없습니다.
