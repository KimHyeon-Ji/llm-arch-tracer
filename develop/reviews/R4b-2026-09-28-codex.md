## Q2 — `inherited/not_revalidated`

**현재 표현이면 충분하다.** 최상위 MANIFEST 에 `base_results_commit`, `inherited_models`,

object 도 `85e33274` 와 동일했다.

브랜치 설명에 "K3 만 갱신되고 나머지 네 모델은 `results@85e33274` 와 바이트 동일" 이라고
한 줄 적으면 사람에게 더 친절하지만 **push 전 필수 수정은 아니다.**

향후 기계 계약에서는 8 자리 대신 **40 자리 전체 commit SHA** 를 쓰는 편이 좋다. 현재는
`85e33274` 가 이 브랜치의 실제 부모이므로 모호하지 않다.

## Q3 — 아직 게이트가 못 보는 부분

상속 모델에 `plus_at/` 이 없으면 **건너뛰는 처분이 맞다** -- 검증할 plus-at 계약 자체가
없기 때문이다.

남은 비차단 hardening 둘:

1. `_check_export()` 는 commit 전 **작업트리**를 검사한다. 향후 `git add -A` 후 **index
   blob 도 다시 해시**하면 수동 clone 과 거의 같은 경로를 자동 검증할 수 있다.
2. destination 저장소가 실행 시작 시 dirty 하면 **상속 모델의 기존 변경을 함께 커밋**할 수
   있다. 시작 시 destination clean 을 요구하거나, inherited 모델의 tree OID 가 실행 전
   HEAD 와 같은지 commit 전에 확인하는 게 좋다.

`.gitattributes` 가 commit 됐는지 별도로 검사하지 않는 문제는 현재 경로에서는 해소됐다
(`2e22cdc5` tree 에 들어 있고 blob 해시도 직접 검증).
