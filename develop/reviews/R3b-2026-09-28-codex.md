# R3b 원문 기록 — 외부 검토(Codex), 2026-09-28

**판정: R3b 상태로는 공개 승인 보류.** 실제 산출물의 A 치환과 residual sidecar 내용은
상당히 잘 정리됐다. 읽기 전용으로 검증했고 파일은 수정하지 않았다.

## 검토자가 확인한 것

- 테스트 11/11 통과, dry-run V1~V8 및 V9 13 게이트 실행
- A footprint 2,080 셀, shape/module/op/axis 이상 0
- `expressions.yaml` 1,262 레코드 (prefill/decode 각 631)
- residual 수식 평가·메타데이터·parameter lineage **독립 검사 이상 0**
- `symbols.yaml` 에서 폐기 MoE 기호 제거 확인

**그러나 "8 개 조건이 모두 해소됐다" 는 주장은 코드 및 생성 문서와 일치하지 않는다.**

## 차단 5 건 (원문 요지)

1. **Residual 분류가 아직 direct consumer 에 의존한다.** `plus_at_resid.py:175` 가 concat 의
   직접 consumer 가 mix op 인지 확인한다. 따라서 "concat 뒤에 view/cast 가 끼는 경우를
   parameter lineage 로 완전히 추적한다" 는 설명은 사실이 아니다. `:220` 의 cardinality 는
   현재 데이터에는 통과하지만 (a) append 가 정확히 `l % R_res == 0` 인 층에만 있는지
   (b) 기대한 module group 이 통째로 누락됐는지 (c) extra/missing mix 와 view/cast 중간
   consumer 를 adversarial fixture 로 잡는지 를 충분히 강제하지 않는다.
2. **Axis-class 게이트가 fail-open 이다.** `plus_at_v9.py:493` 이 crosswalk 나 raw/concrete
   evidence 가 없거나 stale 하면 미평가를 반환하지만 `:592` 가 이를 `not_applicable` 로
   바꾼다. 필수 증거가 없어서 평가하지 못한 것은 N/A 가 아니라 `FAIL` 또는
   release-blocking `not_evaluated` 여야 한다.
3. **`reshape_derivation` 에 같은 op-id number-space 문제가 남아 있다.**
   `plus_at_v9.py:367` 이후 코드는 raw `shapes.concrete.jsonl` 의 op_id 로 만든 맵을
   published table op_id 로 직접 조회한다. 두 번호 공간은 다르므로 현재의
   "원본 이견 0 → 파생 0" 은 유효한 증명이 아니다. crosswalk 를 쓰거나 명시적인
   inherited-proof 방식으로 바꿔야 한다.
4. **DIFF 설명 수정이 실제 코드와 산출물에 반영되지 않았다.** `plus_at_diff.py:87` 은 남은
   literal 목록을 출력한 뒤 여전히 전부 attention-residual 경로라고 단정한다. 생성된 DIFF
   에는 `3840`, `12` 등 MoE literal 도 포함되어 모순이다.
5. **Bundle contract 가 오래된 상태다.** `plus_at_apply.py:726` 은 아직 제거된 `C_trace`,
   `n_trace_regular`, `n_trace_last` 를 필수 trace-control symbol 이라고 명시하며 새
   `expressions.yaml` 을 bundle contract 에 포함하지 않는다.

추가: crosswalk/raw shape/ports/semantic evidence 가 MANIFEST input hash 에 포함되지 않고,
crosswalk 선택도 glob 첫 결과에 의존한다. 공개 재현성을 위해 이 입력들을 pin/hash 하고
duplicate key 및 빈 `raw_sites` 도 거부하는 편이 맞다.

## Q 별 결론

- **Q1** 아직 승인하지 않는다. 짧은 R3c 보완 후 재검토. R1/R2 부터 다시 할 필요는 없다.
- **Q2** 같은 답을 R2/R3 두 파일에 복제하지 말 것 -- 독립 검토처럼 보인다. 이전 통합 답변을
  **R2 기록 하나**로 저장하되 `request_scope: R2+R3` 또는 `covers` 를 명시하고, 이번 답은
  별도 **R3b 기록**으로. 게이트가 파일명만 본다면 장기적으로는 문서의 명시적 `covers`
  필드를 인식하도록 고치는 게 낫다.
- **Q3** `moe_quotient_remainder_consistency` N/A **타당**.
  `prefill_decode_structure` 는 **조건부 N/A** -- main-table A 가 prefill 전용이라는 좁은
  의미에서는 맞지만, bundle 에 양 phase 의 `expressions.yaml` 이 들어가므로 별도의 sidecar
  cross-phase consistency 검사가 필요하다. 독립 검사 결과 두 phase 각 631 개이고 수식 종류별
  분포도 동일했다 -- 이 검사를 V9 게이트로 승격하면 된다.
  반대로 crosswalk 가 없거나 stale 해서 평가할 수 없는 상태를 N/A 로 처리하는 것은
  인정할 수 없다.
- **Q4** 방향은 좋다. main table schema 를 깨지 않으면서 residual recurrence 의미를
  보존하므로 B sweep 소비자에게도 유용하다. 다만 공개 계약에 최소한 다음이 명시돼야 한다 --
  csv/jsonl·symbols.yaml·expressions.yaml 이 하나의 bundle, sidecar join key 와
  canonical-cell 규칙, 사이드카 없는 소비자는 숫자 표만 쓸 수 있고 residual recurrence
  의미는 복원 못 함, prefill/decode consistency 및 sidecar schema/version,
  symbol 참조 무결성.
- **Q5** 그렇다. 가장 중요한 것이 위 3 번 -- **`reshape_derivation` 의 raw op_id ↔ published
  op_id 혼용**이다. axis 게이트에만 crosswalk 를 적용하고 reshape 에는 같은 교정을 하지
  않았다. 따라서 현재 V9 의 reshape PASS 는 승인 근거로 쓸 수 없다.
