# R3d 원문 기록 — 외부 검토(Codex), 2026-09-28

**판정: 공개 승인 보류.** R3d 수정은 실제로 반영됐고 핵심 데이터도 깨끗하지만, 추가 음성
대조에서 아직 발화하는 fail-open 경로를 확인했다. 파일은 수정하지 않았다.

dry-run            14 pass / 2 N/A / 미평가 0
footprint          2,080 셀, digest 동일

## Q1 — `n_chunk` 판정·footprint·사이드카 내용은 계속 승인. V9 일괄 accepted 와 released 는 보류

남은 직접 차단점 넷.

1. **Reshape 의 raw slot 범위가 여전히 fail-open 이다** (`plus_at_v9.py:453`). crosswalk
   slot 의 shape index/axis 가 잘못되면 **해당 변경을 적용하지 않고 넘어간다**. 실제 바뀐
   셀의 crosswalk 에 `i[0] ax99` 를 주입한 음성 대조 결과가 `reshape_derivation → True`,
   `raw op 4485, 이견 0 → 0` 이었다. axis 게이트에는 slot 범위 검사가 생겼지만 reshape
   에는 없다. **같은 raw-slot 검증 helper 를 두 게이트가 공유해야 한다.**
2. **`expression_no_cycle` 이 직접 자기 참조를 놓친다** (`plus_at_v9.py:70`). `t != name`
   으로 self-edge 를 제거하므로 `x: {expr: x}` 가 PASS 했다. 그 조건을 제거하면 기존
   DFS 가 직접 순환도 잡는다.
3. **Sidecar symbol/formula 무결성이 V9 에서 검사되지 않는다.** `g_symbol_declared()` 는
   `ctx["actual"]`, 즉 main-table A 변경만 본다. `sidecar_records` 에 `mystery(l)` 같은
   미등록 식을 넣어도 PASS 했다. 더구나 사이드카의 formula registry 는 overlay 에서
   복사하지만 실제 record 의 `expr` 은 `plus_at_resid.py:111` 의 별도 상수에서 나온다 --
   **두 registry 가 달라도 현재 검사는 잡지 못한다.** 최소한 다음을 검사해야 한다.
   record 의 `formula` 가 registry 에 존재 / `record.expr == formulas[record.formula]` /
   식별자가 sidecar namespace 에 전부 선언됨 / join key 유일성 / 식 평가 결과가 `value`
   와 일치 / overlay 가 사이드카를 선언했는데 records 가 없으면 N/A 가 아니라
   `not_run`/FAIL.
4. **`base_table_symbols` 참조가 현재 dangling pointer 다** (`plus_at_apply.py:786`).
   `inherited_from_authority` 라고만 쓰지만 R3d 가 authority 라고 설명한
   `models/<m>/full/symbol_table.json` 은 실제 저장소에 없다. MANIFEST input 에도 해당
   registry 의 path/hash 가 없다.

## Q2 — `base_table_symbols`

개념은 맞지만 현재 표현은 충분하지 않다. 복제를 피하려면 실제로 존재하는 authority 를
구조화해 가리키고 해시를 고정해야 한다.

```json
"base_table_symbols": {"mode": "external_reference", "path": "...", "sha256": "..."}
```

완전한 base-symbol registry 가 없다면 `inherited_from_authority` 라고 주장해서는 안 되고
`"base_table_symbol_validation": "out_of_scope_trusted_base"` 처럼 범위를 솔직하게
제한해야 한다. 그리고 unknown-symbol 거부 규칙은 +@ 가 추가한 main-table symbol 과
sidecar namespace 에만 적용해야 한다.

`results-plus-at` 브랜치가 단독 소비 가능한 배포물이어야 한다면 외부 registry 의
immutable snapshot 을 bundle 에 포함해야 한다. 저장소와 함께 소비하는 derived view 라면
path + SHA 외부 참조로 충분하다.

## Q3 — 항등식 검사

**(b) 게이트에서 제거하고 falsifiable 한 커버리지 검사만 남기는 것**을 권한다.
`n_ck == len(roots)` 는 같은 crosswalk 로 roots 와 reverse map 을 동시에 구성하므로 현재
구조상 깨질 수 없다. 별도의 `vacuous` 결과를 추가할 필요도 없다. axis 게이트 자체는
crosswalk 전체 셀 coverage / raw slot 존재와 범위 / ports coverage / 등가류 내부 label
충돌 덕분에 여전히 충분히 의미가 있다. 항등식을 남기더라도 내부 assertion 정도로만 두고
PASS detail 의 근거로 세면 안 된다.

## Q4 — 추가 fail-open

- **`zero_axis_only_initial_residual`** (`:145`) 은 `found ⊆ allow` 만 검사한다. 허용
  셀이 선언됐지만 실제 zero 가 0 개여도 PASS 했다. `set(found) == allow` 여야 한다.
  현재 파이프라인에서는 V1/V2 가 보완하지만 게이트 자체는 불완전하다.
- **`sidecar_phase_consistency`** (`:466`) 는 수와 formula 분포만 비교한다. 현재 데이터는
  독립 검사상 normalized record 구조까지 완전히 동일하지만, 게이트는 **서로 다른 셀에
  formula 가 재배치돼도 통과**한다. phase 를 제외한 structural multiset 을 비교해야 한다.
- **`expected_footprint.sha256`** (`plus_at_apply.py:569`) 이 없으면 아직 경고만 하고
  진행한다. `review_status: accepted` 와 SHA 가 모두 필수여야 한다.
- **Source pin** (`plus_at_apply.py:834`) 도 pinned 후보가 없을 때 일반 local/site-packages
  후보로 fallback 할 수 있다. 주석대로 "고정 revision 에 없으면 중단" 하려면 remote-code
  evidence 에 대해서는 pinned path 를 **단독 후보**로 써야 한다. 현재 MANIFEST 의 source
  는 올바른 `f831ab…` snapshot 을 가리키므로 근거 내용 자체는 문제없다.
