## Q3 — snapshot 이 authority 를 사칭할 위험

**현재 구조는 허용 가능하다.** 원본 provenance 가 실제로 Git 에 추적되고 있고
`base_results_commit=d8fec245…` 에도 동일한 blob 이 존재하기 때문이다. 따라서 공개 소비자는
(1) source repository 에서 `d8fec245…` 의 `full/provenance.json` 취득 (2) SHA-256 이
snapshot 의 `origin.sha256` 과 같은지 확인 (3) `/symbol_table` 을 `base_symbols.json` 과
비교 — 이렇게 검증할 수 있다. results 브랜치에 전체 provenance 를 중복 수록할 필요는 없다.

다만 **source repository 나 해당 커밋이 공개되지 않는 배포라면** snapshot 의 계보는 독립
검증할 수 없으므로, 그 경우에는 provenance 원본이나 별도 서명된 attestation 이 필요하다.
