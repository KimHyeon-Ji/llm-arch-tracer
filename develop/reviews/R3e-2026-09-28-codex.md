# R3e 원문 기록 — 외부 검토(Codex), 2026-09-28

**판정: R3e 의 의미론적 산출물은 대체로 승인 가능하지만 `results-plus-at` 공개 승인은
보류.** 짧은 R3f 가 한 번 더 필요하다.

## 검토자가 재현한 것

```
fixture            12/12 통과
negative control   15/15 발화
V9                 16 PASS / 2 N/A / 0 NOT-RUN
footprint          2,080 행, digest 일치

```

## Q1 — 하드 블로커 둘

### 1. V9 외부 승인 상태가 MANIFEST 에 제대로 반영되지 않는다

`plus_at_apply.py:554` 는 `v9_review.yaml` 의 `accepted` 상태로 release blocker 를
제거하지만, 최종 MANIFEST 에는 **원래 `v9_rows` 를 그대로 기록**한다. 따라서 모든 외부
리뷰를 승인해도 MANIFEST 전체 상태는 `released` 인데 개별 `v9.<gate>.review_status` 는
여전히 `proposed` 일 수 있다. 또한 `v9_review.yaml` 자체의 SHA 도 MANIFEST 에 고정되지
않는다.

R3f 에서 최소한 필요한 것:

- 외부 리뷰가 적용된 effective gate status 를 MANIFEST 에 기록
- `v9_review.yaml` 의 SHA-256 기록
- 리뷰 파일의 dirty/uncommitted 상태도 release 시 차단

### 2. `base_symbol_authority` 외부 참조가 **현재 exporter 구조상 실제로 깨진다**

`sync_results_branch.py:227` 이후 로직은 `full/` 을 결과 브랜치에서 제거한다.
`sync_results_branch.py:240` 의 carry 목록에도 `provenance.json` 이 없다. 따라서 현재
계약의 `models/<model>/full/provenance.json#/symbol_table` 포인터는 `results-plus-at`
소비자에게 **dangling reference** 가 된다.

## Q2 — symbol table 외부 참조 허용 여부

**현재 구조에서는 허용하면 안 된다.** 가장 안전한 방식은 `plus_at/base_symbols.json`
같은 최소 불변 snapshot 을 bundle 에 포함하는 것이다. 권장 구성: 사용된 base symbol 과
값 / 원본 provenance 파일 SHA-256 / 모델별 coverage 결과 / snapshot 자체 SHA-256 을
MANIFEST 에 기록.

`full/provenance.json` 을 results exporter 가 보존하도록 바꿀 수도 있지만, plus-at
bundle 을 독립 검증 가능하게 만드는 **최소 snapshot 방식이 더 명확하다.**

## Q3 — 추가할 negative control

우선순위가 높은 누락 항목:

```
shape_index=-1, axis=-1 거부
raw symbolic row 와 concrete row 의 rank 가 다른 경우
x -> y -> x 형태의 다중 노드 표현식 순환
V9 리뷰 승인 후 MANIFEST 개별 상태도 accepted 가 되는지
v9_review.yaml 누락·변조·dirty 상태에서 release 차단
export 후 base_symbol_authority 참조 파일이 실제 존재하고 SHA 가 맞는지
pinned source 가 없을 때 우연히 같은 이름의 로컬 파일로 fallback 되지 않는지
reshape disagreement 가 다른 위치로 이동했지만 총개수는 같은 경우
```

특히 `_bad_slots`(`plus_at_v9.py:388`)는 **상한은 검사하지만 음수 인덱스를 거부하지
않는다.** 파이썬의 음수 indexing 때문에 마지막 slot 이 수정될 수 있으므로 fail-open
여지가 있다.

## Q4 — 남아 있는 tautology / fail-open

- R3e 문서의 설명과 달리 **`n_ck == len(roots)` 검사는 아직 남아 있다**
  (`plus_at_v9.py:861`). 현재 결과도 사실상 `69 == 69` 다. 독립적인 증거가 아니므로
  제거하거나 diagnostic 으로 명시해야 한다.
- 사이드카의 structural multiset 이 이미 formula/expr 까지 포함하므로, 뒤의 **formula
  distribution equality 검사는 중복 조건**이다.
- **reshape disagreement 도 현재는 총개수만 비교한다** (`plus_at_v9.py:495`).
  `tot_n > tot_o` 만 차단하면 한 disagreement 가 사라지고 다른 위치에 새로 생긴 경우
  통과할 수 있다. 행별·op 별 집합 비교가 필요하다.
- R3e 문서의 `prefill 21 / decode 21` 은 실제 결과인 **`prefill 21 / decode 19`** 로
  정정해야 한다.

> 제거' 로 제한해 수정하면 이후 공개 승인이 가능합니다."
